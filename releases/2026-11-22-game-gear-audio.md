# 2026-11-22 ゲームギアの音声の採取と I/O ポートの監視

直前の版は `akiyan-2026-11-21-unthrottled` で取得できる。 [本体の変更](https://github.com/akiyan/MesenCE/commit/0325972de11580d44871cb2a7e5b0d2ce347af14) · [Issue #7](https://github.com/akiyan/MesenCE/issues/7) · [再実行手順](../docs/setup.md)

SFC 用だった音声の採取を機種によらない `emu.startAudioCapture` / `emu.getAudioCapture` にし、マスターシステムとゲームギアでも使えるようにした（SFC の名前も残す）。
PSG の書き込み（ポート `$40`〜`$7F`）とゲームギアのステレオ（ポート `$06`）を `psg_write` / `psg_stereo` の行として記録する。採取できるフレーム数の上限は 3,600 から 216,000 にした。
ヘッドレス実行では、コアの既定で 0 だった PSG の各チャンネルの音量を GUI の既定の 100 にした（それまで WAV が無音になった）。
Lua のメモリコールバックが `emu.memType.smsPort` で呼ばれなかったため、絶対アドレスのないポートの読み書きはその種別のまま照合するようにした。

`tests/headless_gg_audio.py` が生成するゲームギアの ROM は、左だけに出した矩形波の音量を毎フレーム切り替える。新規プロファイルで 2 回実行し、次の結果が一致した。

| 確認 | 結果 |
|---|---|
| フレーム | 8 フレーム、48 kHz で 6,408 サンプル。各フレームのサンプル数がマスタークロックと 2 サンプル以内で一致 |
| PSG の行 | 1 フレームに 1 行、ポート `$7F` に `$90` と `$94` が交互。すべて採取の区間内で時刻順 |
| 出力 | 左に波形があり、右は無音（ステレオ `$F0`） |
| Lua | ポートのコールバックが設定の 3 回と毎フレームの書き込みを数え、ステレオの `$F0` を受けた。2 つ目の採取の開始は拒否された |
| 再現 | WAV と JSONL が 2 回の実行でバイト単位で一致 |

従来の試験 6 本（SFC 一括実行、ゲームギア一括実行、名前付きステート、外部制御、PPU、SFC の音声）も通った。
利用側（kamaitachi-ops）では、変換したゲームギア版の全編（約 12 万 8 千フレーム）で PSG の書き込み 67,740 回を記録し、ROM の音楽データから求めた書き込みと一致した。
